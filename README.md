# Лабораторная работа №2: Параллельное умножение матриц (OpenMP)

## 1. Цель работы
Исследование эффективности параллельных вычислений при умножении квадратных матриц с использованием технологии OpenMP. Анализ ускорения (Speedup) и эффективности параллелизации в зависимости от количества потоков и размерности задачи.

## 2. Конфигурация тестовой системы
- **Процессор**: 8 физических ядер
- **Тестовые размеры матриц (N)**: 200, 400, 800, 1200, 1600, 2000
- **Количество потоков**: 1, 2, 4, 8

## 5. Анализ результатов

### Ключевые выводы:
1. **Максимальное ускорение**: Достигнуто значение **4.85x** для матрицы 400×400 при использовании 8 потоков. Это близко к линейному масштабированию, но не идеально из-за накладных расходов на создание потоков и синхронизацию.
2. **Эффективность параллелизации**:
   - **2 потока**: Эффективность составляет 94–102% (почти идеальное масштабирование).
   - **4 потока**: Эффективность варьируется от 60% до 99%. Наблюдается хорошая масштабируемость.
   - **8 потоков**: Эффективность падает до 43–60%. Это связано с тем, что задача становится ограниченной пропускной способностью памяти (memory-bound), а также возможны конфликты кэшей между ядрами.
3. **Производительность (GFLOPS)**:
   - Пиковая производительность **2.67 GFLOPS** достигнута на матрице 400×400 с 8 потоками.
   - Для больших матриц (N ≥ 1600) наблюдается снижение производительности в расчете на один поток из-за кэш-промахов (cache misses). Данные перестают помещаться в L3 кэш процессора, что увеличивает задержки доступа к оперативной памяти.

### Проблемы и наблюдения:
- **Аномалия при N=800, 4 потока**: Ускорение составило всего 2.41x (эффективность ~60%). Вероятная причина — неравномерная нагрузка или конфликты доступа к памяти в данной конкретной конфигурации кэша.
- **Снижение эффективности на больших N**: При N=2000 эффективность 8 потоков составляет 57.9%. Это подтверждает гипотезу о том, что для задач с интенсивным использованием памяти (как умножение матриц) простое увеличение числа потоков не дает линейного роста производительности после определенного предела.

## 6. Заключение
Реализация параллельного умножения матриц с помощью OpenMP демонстрирует значительный прирост производительности по сравнению с последовательным алгоритмом. Однако, из-за архитектурных ограничений (кэш-память, шина памяти), линейное ускорение недостижимо для больших объемов данных. Оптимальная конфигурация зависит от размера матрицы: для малых размеров выгодно использовать больше потоков, тогда как для очень больших матриц эффективность параллелизации снижается.
